## Processo de atualização

1. Uma mudança é feita no kit (componente novo, token, regra).
2. A descrição do componente é preenchida no Figma (regra obrigatória).
3. Uma IA com acesso ao Figma exporta variáveis e inventário e compara com a versão anterior.
4. As páginas afetadas são atualizadas e marcadas como “em revisão”.
5. Alguém do time revisa e aprova.
6. O changelog recebe a entrada com versão e data.

O texto desta documentação fica em arquivos MDX no repositório do GitHub, e os dados do Figma em arquivos JSON. Cada mudança entra por pull request, que é onde acontece a revisão do time antes de publicar. <Badge kind="rec" />

- Referências antigas ainda na página Componentes ou fora dela: Button (referência antiga de botões), Slider, Filters (Drawer), Icon Button / Favorite, angulo-direito (1) 2, Text Field (página Layout Mobile), Filtros Departamento / Simples / Preço (página Layout Mobile, ainda fora da página Componentes), Faixa de benefícios, Faixa de Brinde, Faixa de Frete Grátis (página Layout Mobile, sem descrição).

- Versões desktop dos componentes e telas; proposta de alternar mobile/desktop só redimensionando o frame (backlog C36).
- `layout/header-padding-top` provisório; grid de colunas e largura máxima no desktop não definidos.
- Política de foco por teclado nos botões (o estilo `focus-ring` existe, mas não é usado).
- Ferramentas de IA aprovadas e permissões de edição do arquivo base.
